# 03 运行与审核流程

本项目将数据检查、Agent 分析、自动验证和人工审核分为独立阶段。任何单一阶段通过，都不代表整份业务报告已经获批。

## 运行模式

| 模式 | 是否调用模型 | 用途 | 成功状态 |
|---|---|---|---|
| `check` | 否 | 检查字段、类型、重复、日期、折扣范围和数据摘要 | 数据门禁通过 |
| `demo` | 否 | 用固定模拟交互验证 SQLite、工具循环、报告校验和审计落盘 | `awaiting_human_review` |
| `ping` | 是 | 用最小请求验证模型服务连接 | 返回模型响应 |
| `run` | 是 | 执行真实工具调用分析 | `awaiting_human_review` 或明确失败状态 |
| `review` | 否 | 对已生成的原始报告追加人工决定 | 追加审核记录 |

`demo` 与 `run` 使用相同的本地数据、SQLite 查询和报告验证链路，但 `demo` 的调用序列是固定脚本，不能用来代表模型分析能力。

## 状态流转

```text
数据加载
  ├─ 质量失败 -> data_failed（模型调用为 0）
  └─ 质量通过
       ├─ 模型/协议/连接失败 -> failed
       ├─ 达到轮次上限 -> round_limit
       ├─ 达到工具调用上限 -> tool_limit
       └─ 报告通过有限自动校验 -> awaiting_human_review
```

`awaiting_human_review` 只表示程序允许报告进入人工审核，不表示报告已经批准。

## 自动验证负责什么

- 报告必填字段和固定分析范围。
- 商品交易明细粒度声明。
- sales、profit、profit_margin、order_count 四项核心指标。
- 事实引用的 query、row、column 和 value 是否存在且一致。
- 排名主张的比较列、方向和极值行。
- 观察性证据等级、未验证假设和人工决策要求。
- 已知越界表述，例如在没有因果识别时给出精确货币增量预测。

自动验证是有限规则集合，不尝试证明所有自然语言含义正确。

## 人工审核负责什么

- 业务口径是否与问题一致。
- 是否遗漏与结论冲突的重要事实。
- 调查优先级是否使用清晰且一致的标准。
- 描述性关联是否被误写为原因或干预效果。
- 建议是否依赖当前不存在的成本、库存、退货或客户数据。
- 报告是否适合预期用途，以及是否需要 `approve`、`revise` 或 `reject`。

审核通过也不意味着统计显著、因果成立或未来收益得到保证。

## 审计与不可覆盖原则

每次运行创建独立的 `runs/时间_随机编号` 目录，保存：

- `manifest.json`：模式、模型、问题、资源限制和源码哈希。
- `state.json`：最终状态、轮次、调用次数、耗时和 usage。
- `events.jsonl`：模型消息、工具调用和验证结果。
- `queries.json`：SQL、列、结果、截断状态和耗时。
- `report.json` / `report.md`：通过有限自动校验的原始报告。
- `human_reviews.jsonl`：追加式人工审核决定和原报告哈希。

原始报告不因后续修订而覆盖。修订稿和修订稿审核使用独立文件，并引用源报告哈希，以保留完整决策链。

## 验收原则

项目验收至少覆盖以下场景：

1. 正常品类分析：核心指标、下钻和证据引用正确。
2. 换对象分析：更换 category 后不复用上一次结论。
3. 证据不足问题：拒绝没有反事实支持的精确收益估算。
4. 数据质量失败：在模型调用前阻断，避免费用和错误分析。
5. 已知失败回归：把真实错误转成离线 Evaluation，修复后重复验证。
