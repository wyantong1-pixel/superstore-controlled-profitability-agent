# 09 项目阶段总结

日期：2026-09-21。

## 项目定位

本项目是一个受控的盈利分析 Agent。模型负责理解业务问题、选择下钻方向并调用只读 SQL 工具；本地程序负责数据门禁、权限限制、核心指标与证据校验；人负责审核业务解释、因果边界和行动建议。

项目目标不是让模型自动做经营决策，而是把 AI 分析变成可追溯、可拒绝、可修订的决策支持流程。

## 工作流程

1. 人提出业务问题并固定分析范围。
2. Agent 读取字段、数据粒度、指标口径和工具限制。
3. Agent 自主生成只读 SQL，先看总体，再按子品类、地区、折扣等维度下钻。
4. 本地程序执行 SQL，保存查询与结果，并校验核心指标、证据单元格、排名和报告结构。
5. 报告只能进入等待人工审核状态，不能自行批准或执行调价等业务动作。
6. 人工检查事实是否完整、优先级是否合理、观察关联是否被误写成因果。
7. 原报告有问题时记录 `revise`，再基于同一证据生成独立修订稿；原始报告和审核记录不被覆盖。

## 已完成验证

| 阶段 | 结果 | 关键发现 |
|---|---|---|
| Furniture 首次真实运行 | 程序通过，人工 `revise` | 模型错误解释折扣排名，并越过因果和行动边界 |
| 证据不足问题首次完整验收 | `round_limit`，不通过 | 单行 SQL MAX 被验证器误伤；候选报告仍给出无依据的精确收益金额 |
| 离线修复 | 53 项测试、12/12 Evaluation 通过 | 增加排名复算、粒度、术语、因果、行动和精确金额预测等规则 |
| Furniture 修复后复验 | 程序通过，原报告 `revise` | 正确拒绝估算取消折扣收益，但仍把 Tables 错称为唯一亏损子类 |
| Furniture 独立修订稿 | 人工接受 | 修正 Tables/Bookcases、统计术语和商品明细粒度 |
| Office Supplies 换对象验收 | 泛化通过，原报告 `revise` | 范围和数值正确切换，但优先调查对象缺少统一标准，部分行动缺数据 |
| Office Supplies 独立修订稿 | 人工接受 | 按利润率严重程度、子品类整体表现和地区异常分别确定排查理由 |

换对象验收表明系统没有把 Furniture 的数值和结论直接套用到 Office Supplies；同时也说明程序校验通过不等于业务报告可以批准。

## 关键失败与改进

1. **标签正确不等于排名正确。** 排名事实现在必须声明比较列和 `min/max`，程序用完整未截断结果集复算。
2. **验证规则也会误伤。** 单行 SQL 已用 `MAX()` 计算极值时，不再被当作多行排名强制要求 `comparison`。
3. **结构化声明可能与自由文本矛盾。** 当报告声明没有估计因果效应时，摘要、假设和行动中的精确货币增量预测会被拒绝。
4. **自动校验不能替代业务审核。** “Tables 是唯一亏损子类”和 Office Supplies 调查优先级问题都通过了程序校验，却被人工语义审核发现。
5. **修订不能覆盖历史。** 原始报告、查询、状态、哈希、正式审核和修订稿分别保存，能够还原一次结论怎样被拒绝和改进。

## 人与系统的分工

| Agent / 程序 | 人工分析师 |
|---|---|
| 读取契约、生成 SQL、执行限定下钻 | 定义业务问题、范围和风险边界 |
| 计算指标、保存证据、校验数值与排名 | 判断口径是否合理、结论是否遗漏重要事实 |
| 标记假设与限制，提出核查或试验建议 | 判断观察关联、因果主张和行动建议是否成立 |
| 保留运行日志和不可覆盖的原始报告 | 决定 approve、revise 或 reject，并验收修订稿 |

## 当前结论与边界

项目已完成真实模型工具调用、受限 SQL 执行、有限自动验证、人工语义审核、失败回归和换对象验收。两份脱敏修订报告见 `examples/`。

当前没有进行因果识别或真实业务执行，也没有足够的重复在线样本来估计模型总体准确率或长期稳定性。系统不能自动调价，观察数据不能证明折扣的因果效果，测试结果也不代表生产级数据平台能力。

下一阶段如需继续验证，应预先定义重复次数、通过标准和费用上限，再进行稳定性测试；不应为了得到一次“通过”而连续调用模型。
