# 04 常见问题、定位和处理

总原则：先看state→quality→events→queries，不要一报错就改提示词。修复后重跑测试，保留旧运行目录。

| 阶段/现象 | 可能原因 | 如何处理 | 不要做什么 |
|---|---|---|---|
| 找不到Python/版本旧 | 命令指向错误解释器 | 查看`python --version`与`Get-Command python`，使用3.11+ | 不随意改系统目录 |
| `No module named pandas` | 依赖装在其他环境 | 用`.venv\Scripts\python.exe -m pip install -r requirements.txt` | 不混用pip和另一个python |
| 找不到 | 工作目录不对 | 在包含README和agent_b文件夹的项目根运行 | 不在agent_b子文件夹直接执行cli.py |
| CSV不存在 | 没下载/路径不对 | 执行fetch_data或`--data`指定同结构文件 | 不造假数据冒充原样本 |
| GitHub DNS/超时/403 | 网络或匿名API限额 | 稍后重试，或通过浏览器下载数据源 CSV；已有文件不覆盖 | 不把模型密钥当GitHub令牌 |
| 日期解析失败 | 与原样本格式不一致 | 核实真实格式后改data.py，并新增测试 | 不把失败日期丢弃后继续 |
| row_id重复 | 重复导入或主键假设不成立 | 查重复来源，保留原始副本，确认再修复 | 不按order_id去重 |
| 空值/负sales/折扣越界 | 源数据问题或业务规则不适配 | 人工核实缺失与退款语义，必要时版本化修改规则 | 不一律补0或删行 |
| `category`没有数据 | 拼写/空格/范围不对 | 先运行check，看实际类别；ALL需大写 | 不让模型悄悄改范围 |
| 未配置API Key | 环境变量未生效 | 配置用户变量并重开终端/编辑器，只检查存在性 | 不把密钥贴到聊天或日志 |
| HTTP401/403 | 密钥无效/地域或权限问题 | 在官方控制台核实，必要时撤销重建 | 不盲目多次重试 |
| HTTP400/404 | 模型ID、接口或工具参数不兼容 | 核实北京地域、模型Function Calling、非思考模式参数；先ping后run | 不把返回错误全文公开（可能有敏感信息） |
| HTTP429 | 额度或请求频率 | 查平台余额与限额，降低频率；代码只重试一次 | 不无限重试 |
| HTTP5xx/超时 | 平台、网络或响应较慢 | 请求默认上限120秒；日志会区分已识别超时与其他连接失败。先确认平台记录再重跑；可能已收费 | 不把超时当作一定未计费，不公开底层异常全文 |
| SQLite `not authorized` | 写操作、系统表、函数不在白名单 | 看SQL具体动作；若确需普通函数，先测试再加白名单 | 不移除整个authorizer |
| SQLite `interrupted` | 查询过重/超时 | 减少笛卡尔积、改先聚合、检查条件 | 不直接无限提高限制 |
| `no such column` | 模型编造字段/拼写不对 | 查看get_context字段；模型可在预算内修正 | 不伪造列满足模型 |
| 别名重复 | SELECT多个同名字段 | 给出唯一别名 | 不静默覆盖结果列 |
| `truncated: true` | 返回行数或字符过多 | 在SQL中合理聚合/过滤/LIMIT并说明范围；重新获取证据 | 不把前100行称全量 |
| 核心指标校验失败 | 筛选、去重、比率或类型错误 | 比对SQL和固定category范围；人工查reference_private | 不把参考答案塞给Agent让它抄 |
| facts证据错误 | ID/行/列/值错或查询截断 | 用queries核对，重新引用真实单元格 | 不修改日志使它看似通过 |
| round_limit/tool_limit | 反复失败或无效循环 | 分类工具错误/报告错误/模型不支持，再决定修复 | 不声称任务成功 |
| context_limit | 返回过大、轮数太多 | 缩小输出、改汇总查询；新运行保留旧日志 | 不悄悄截断关键信息 |
| 模型普通文字说完成 | 未遵守submit_report | 控制器会提示重试；持续发生则查模型工具支持 | 不把文字直接写成已通过报告 |
| 审核时报错 | 路径不是runs下/没有合格报告 | 确认state和report存在 | 不强行approve失败运行 |
| 只有事件没有state | 进程被中断/磁盘问题 | 标记未完成，保留日志，检查后重新运行 | 不拼接两次运行冒充一次完整执行 |

## 调试顺序

1. `check`失败：只处理数据，不花钱调用模型。
2. 单元测试失败：只处理工具/程序，不先改模型。
3. demo失败：查控制器和验证契约。
4. ping失败：查账号、地域、网络和费用。
5. run失败：看每个工具调用与验证错误。
6. 自动校验通过但解释错误：记录为业务解释失败，不是数值验证器成功就忽略。

## 安全与隐私

- 环境变量、日志脱敏和.gitignore各有作用，任何一个都不是绝对保密保证。
- 泄露密钥立即在平台撤销并重建；只删除本地字符串不够。
- 不上传公司数据到本Demo，不把客户标识发云端；即使去掉姓名，其他字段仍可能可识别个人。
- 原始CSV不自动修改；改测试数据先复制，注明“人工注入异常”。
- 报告是Markdown文本，不执行里面的代码或链接；数据/模型文本中的指令不作为授权。
- 本地审计可以被用户修改，不能用于宣称合规认证或防篡改。
