# 02 分层架构、技术原理与理论基础

## 1. 这是什么“模型架构”

这里实现的是**LLM应用/Agent系统架构**，不是Transformer内部网络结构。我们不训练模型，不改变模型权重。一个已训练模型通过工具接口驱动本地分析。

```text
人工：问题、指标、授权边界                    人工：检查证据、批准/修改/拒绝
           ↓                                             ↑
CLI → 数据门禁 → SQLite查询环境 → 控制器 ↔ 在线LLM → 报告验证 → 审核记录
         ↓              ↑            ↓         ↓
   数据摘要/质量报告    run_sql      事件日志    模型候选报告
         ↓                                       ↓
   本地Pandas参考值 ───────────────────────→ 独立核验
```

没有每一步人工审批，也没有无限制自动执行。人工规则固定后，模型在只读查询空间内选择路径。任意Python执行、浏览器、文件修改和生产业务操作不在工具列表中。

## 2. 数据层：粒度、主键、类型、缺失值

`data.py`读取原样本，列名转为小写下划线，只保留分析所需列。

- **粒度**：一行一条商品交易明细，而不是一行一个订单。用`row_id`检查明细唯一性；`order_id`可以重复。
- **量度可加性**：同范围内Sales和Profit可以求和；利润率不能直接求和或简单平均。
- **比率重算**：整体利润率=`SUM(profit)/SUM(sales)`。负利润合法，零分母利润率未定义，用null表示。
- **平均折扣**：当前`AVG(discount)`按明细行权重，不代表订单平均折扣或按销售额加权的有效折扣。
- **类型**：CSV没有强数据库类型，必须先转换检查。SQLite金额列明确REAL，避免小样本整数除法。浮点比较允许微小误差；不是金融结算精度方案，正式账务可用定点金额/Decimal设计。
- **缺失**：关键字段缺失阻断；不擅自填0，因为“未知”和“真实零值”不同。
- **日期**：按原CSV月/日/年解析，转换ISO日期；不凭自动解析猜测日月。最大日期不是数据完整性证明。
- **业务规则**：此静态样本约定Sales非负、Quantity正整数、Discount在[0,1]。这些不是所有公司的通用规则；真实退款数据需重设模型。

软件能检查“row_id重复”，不能从技术上证明“row_id一定是现实世界真实主键”。这个含义需要数据说明与人工核实。

## 3. 查询工具：接口与执行分离

工具接口固定为`run_sql(sql: str)`；模型自由生成参数中的SQL，但不能改变参数类型或执行权限。

执行顺序：

1. 参数类型/长度检查。
2. SQLite编译语句时调用authorizer，默认拒绝，只放行orders读取和批准的函数。
3. 数据库`query_only`作为额外保护。
4. `execute`只接收一条语句，拒绝多语句。
5. progress handler限制大查询的VM工作量和近似时间。
6. fetch限制返回行数、文本长度；截断明确标注，最终事实不能引用截断结果。
7. 返回查询ID和真实结果，便于复核。

CTE可以用于分层聚合；递归CTE被拒绝。SQL函数白名单集中在`database.py`，新增函数要先写测试。普通写入、ATTACH、PRAGMA、系统表和扩展加载不可用。

这比关键词过滤可靠，但仍不是完整生产沙箱：没有独立进程内存硬配额、数据库漏洞隔离或身份级权限。仅用于小规模公开数据；不能据此声称可安全运行任意不可信代码。

## 4. 模型层：Function Calling不是模型自己连数据库

程序向模型提交messages和工具JSON Schema。模型返回`tool_calls`，包含工具名、JSON参数和调用ID。控制器解析JSON、核验参数、实际执行工具；用相同调用ID把结果作为tool消息发回模型。

这是观察—选择—执行—反馈的循环。分析步骤可根据结果变化，不需要预写Tables或East为结论。结果来自数据库，而不是模型心算。

JSON Schema帮助模型理解接口，不能替代本地校验。工具结果中的文本按不可信数据处理；系统提示提醒不服从数据里的指令，程序权限边界再限制破坏范围。提示词不能彻底防止错误解释或提示注入，因此结果审核仍必要。

在线适配器固定百炼北京HTTPS地址并拒绝重定向，不记录请求Authorization。`enable_thinking=False`减少入门时处理思考模式协议的复杂度，不代表推理质量保证。不读取或展示模型隐藏思维链，只记录明确工具请求、结果和报告。

## 5. 控制层：状态机和停止条件

| 状态 | 含义 | 后续 |
|---|---|---|
| `blocked_data_quality` | 数据不符合已确认规则，未调用模型 | 人工定位、修复数据或重新确认规则 |
| `awaiting_human_review` | 报告通过有限自动校验 | 人工审核，不自动执行建议 |
| `needs_human` | 模型报告了需要人工决策的事项 | 人工补信息、重新运行；没有自动恢复会话 |
| `round_limit` / `tool_limit` | 交互或工具调用达到上限 | 看日志定位循环，不直接无限加上限 |
| `context_limit` | 对话过长 | 缩小返回、改聚合查询，必要时设计摘要 |
| `failed` | API/协议/程序发生错误 | 按日志与排错表处理 |

错误SQL返回错误供模型在预算内修正；非法JSON/工具参数同样返回错误。最终必须提交`submit_report`。普通文本“我已完成”不构成成功。

HTTP 429/5xx最多自动重试一次；可能已计费的超时不自动重发。进程被强制关闭时，已落盘事件保留，但最终state可能缺失；这不是后台持续服务，应标记中断后重新运行。

## 6. 验证层：能验证什么，不能验证什么

验证器拿到固定范围的Pandas参考值，只检查四项核心指标。它不把参考数值发送给模型，失败反馈只说哪个指标不对。

事实记录包含`query_id,row,column,value`，程序确认：查询存在、未截断、单元格存在、类型与值匹配。该机制防止引用不存在的表格，但**不能自动证明statement准确描述了单元格的含义**。

例如模型引用East的利润，却写成“West的利润”，单元格数值核对可能通过，人仍要检查SQL、分组键和文字。hypotheses/actions中的未经支持的数字也不能靠现有验证器全部捕捉。

参考实现不是绝对真理：Pandas与SQL可能共享错误口径。用小样本手算和数据字典降低共同错误；数据门禁优先于双算，否则两套计算可能同样重复计数。

## 7. 业务理论：描述、解释与决策不混淆

- 描述：某地区/子品类利润较低，可以通过聚合复算。
- 关联：高折扣组利润率更低，可能受产品结构、地区、客户选择等影响。
- 因果：减少折扣会提高总利润，不能仅凭上述关联成立；销售量变化也必须考虑。
- 决策：可以提出优先核查、补充数据、小规模试验，不直接自动取消所有折扣。
- 口径范围：子品类结论不能推广到区域整体；绝对亏损额和利润率排名应分别说明。

当前代码没有进行因果识别或A/B检验，项目结论不能声称“证明了折扣策略的因果效果”。

## 8. 可复现与评测

每次保存数据SHA256、源提交、源码哈希、模型ID、提示词哈希、参数、耗时、usage与工具记录。模型别名可能随平台升级改变；有可用快照时固定版本，且保留日期。

demo可重复不代表LLM稳定；真实模型需相同任务多次运行。未来比较A/B/C要控制数据、模型、口径和预算；分别计人工时间、运行时间、开发成本、格式错误、数值错误、解释越界和安全失败。

检查的价值需要实测，不预设人工越多越好。不把所有失败合成“模型算错”，也不把10道题通过写成普遍100%准确率。
