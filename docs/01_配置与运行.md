# 01 配置、执行与结果查看

本文按 Windows PowerShell 编写。所有命令在 `superstore_agent_b` 目录执行，不在 `agent_b` 子目录执行。

## 1. 你需要手动准备什么

| 项目 | 是否必须 | 怎么处理 |
|---|---|---|
| Python 3.11及以上 | 是 | 先 `python --version`；建议项目单独虚拟环境 |
| 现有Superstore CSV | 是 | 已提供下载脚本；也可从自己的旧仓库复制到 `data/Sample - Superstore.csv` |
| 百炼账号与模型API服务 | 在线需要 | 自己注册/开通，确认北京地域与模型可调用；无需训练或买显卡 |
| `DASHSCOPE_API_KEY` | 在线需要 | 只存本机用户环境变量；不要发聊天、截图或Git |
| `BAILIAN_MODEL` | 可选 | 默认 `qwen-plus`；更换后重新测工具调用，不能默认接口完全兼容 |
| 调用预算 | 在线需要 | 在平台设置可用的额度提醒/限制；程序不保证人民币硬上限 |
| 口径和审核判断 | 是 | 按03文档自己核实，不让模型替自己批准报告 |

在线当前固定百炼北京接口，不支持随意输入代理地址，以免密钥误发第三方。不保证其他地域API Key适配。

## 2. 建环境，不必激活脚本

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

后面一直调用 `.venv` 内的 Python，可避免激活脚本被PowerShell执行策略拦截。不要为了本项目全局关闭执行策略。

如本机 `python` 指向其他解释器，先检查 `Get-Command python`。安装失败要检查网络和包来源，不随意执行网上的未知安装脚本。

## 3. 数据准备与质量检查

```powershell
.\.venv\Scripts\python.exe scripts/fetch_data.py
.\.venv\Scripts\python.exe -m agent_b check
```

下载脚本固定当时的Git提交，保存 `source_manifest.json`，下载失败不会伪造数据。已有CSV不覆盖。你也可以指定别处的同结构CSV：

```powershell
.\.venv\Scripts\python.exe -m agent_b check --data "D:\你的项目\data\Sample - Superstore.csv"
```

检查成功需要 `passed: true`。默认日期按原样本 `月/日/年` 解析；如果替换数据，不得简单把错误值强制转成空值后继续。先核实真实格式。

检查失败先停下。不要为“让Demo成功”自动去掉失败行。数据完整性不能仅凭最大日期判断。

## 4. 先做不收费的离线验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m agent_b demo --category Furniture
```

`demo`使用固定脚本模拟模型消息，只验证本地控制循环与计算链路。它会真的查SQLite，但没有LLM推理，不可写成“AI实测成功”。

命令输出新的结果目录。自动检查通过的状态是 `awaiting_human_review`，不是 `approved`。

## 5. 配置密钥：不把值写进代码

在Windows搜索“编辑账户的环境变量”，进入“用户变量”→“新建”：

- 变量名：`DASHSCOPE_API_KEY`
- 变量值：你在百炼控制台创建的真实密钥。

可选增加 `BAILIAN_MODEL`，值为账号可访问且支持工具调用的模型ID。默认不必设置。

保存后重启运行Python的编辑器和终端。只检查是否存在，不打印内容：

```powershell
.\.venv\Scripts\python.exe -c "import os; print('已配置' if os.getenv('DASHSCOPE_API_KEY') else '未配置')"
```

本项目**不自动读取 `.env` 文件**。只创建`.env`不会生效；选环境变量一种方式即可。环境变量不是加密保险箱，同账号程序可能读取。

## 6. 先连通，再做在线分析

```powershell
.\.venv\Scripts\python.exe -m agent_b ping --allow-cloud
.\.venv\Scripts\python.exe -m agent_b run --allow-cloud --category Furniture
```

`ping`发送一句简单请求，可能产生小额费用，不发送销售数据。成功只说明API连通。

`run`发送问题、业务说明、工具定义、SQL与查询结果。CSV不整份上传，姓名地址等列也未提供给查询环境，但仍不是“数据完全不出本地”。只用于公开样本，不接未经授权的公司数据。

更换分析对象与问题：

```powershell
.\.venv\Scripts\python.exe -m agent_b run --allow-cloud --category "Office Supplies" --question "分析该品类盈利表现，给出优先核查方向，并区分事实与假设。"
```

第一版的核心指标范围是 `category + 全数据周期`。不要只在自然语言问题里要求“九月核心指标”，程序仍会按全周期校验。要做日期筛选需下一版显式增加日期参数。

## 7. 看哪些输出

| 文件 | 作用 |
|---|---|
| `manifest.json` | 模式、模型、问题、配置、数据摘要、源码摘要、Python/Pandas版本 |
| `quality.json` | 强制数据检查通过/失败与警告 |
| `reference_private.json` | 仅本地使用的Pandas核心参考值；不发送模型，不随手加入提示词 |
| `events.jsonl` | 模型可见输出、工具请求和返回、候选报告、校验失败 |
| `queries.json` | 成功查询的SQL、结果、证据编号、截断与耗时 |
| `state.json` | 最终状态、总耗时、调用次数、平台返回的usage |
| `report.json` / `report.md` | 有限自动校验通过后才生成，仍待人审 |
| `human_reviews.jsonl` | 你主动审核后追加；包含决定、理由、报告哈希与时间 |

数据失败或运行上限中止可能没有报告，这是预期行为，不是空报告也算成功。日志可能含公开样本的明细ID、SQL与问题，分享前仍需检查。

## 8. 人工审核怎么执行

先打开报告、查询证据和参考值，按03文档核查。再将下面路径替换成实际运行目录：

```powershell
.\.venv\Scripts\python.exe -m agent_b review --run-dir "runs\实际运行目录" --decision approve --reviewer "你的名字" --note "已复算四项核心指标；已核对主要查询；未发现越界因果表述，仅作为历史描述性分析采纳。"
```

`approve`=本地记录采纳；`revise`=需修改；`reject`=拒绝。理由必须真实，不要直接复制示例当完成检查。审核记录是本地可编辑文件，不具备组织身份认证或防篡改能力。

审核不改变原报告，不发邮件、不调价、不写业务数据库。修改后的报告应重新运行生成新的目录，再复审，不覆盖旧证据。

## 9. 费用与运行限制

默认最多10轮模型交互、18个工具调用；单次查询约2秒/200万VM指令、最多100行/24000字符；上下文字符限制100000。单次模型请求默认最多等待120秒。HTTP 429或5xx仅重试一次；超时不自动重试。

字符不等于token；重试可能产生额外计费；`usage`缺失表示未知，不能视为0。总耗时包括网络和程序，并非人工工时。费用按实际平台价格核算，不能把离线耗时与真人工作成本直接等同。
